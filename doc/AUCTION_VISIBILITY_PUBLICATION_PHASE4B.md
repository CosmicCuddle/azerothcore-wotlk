## Implementation and source evidence

- Searcher previously started the worker before initializing its queue pointers/stop flag. Start only after initialization, idempotent Stop and destructor join. Remove worker-local update queues and shared mutable auction records; catalog owns canonical per-faction maps of shared immutable entries. Add/remove/bid serialized by catalog mutex; bid uses copy-on-write pair. Capture immutable View once per dirty faction, attach to request; all workers share the pinned view, never mutate catalog or read live Player/Item/template/DBC. Capture item/search/recipe facts and names at AddAuction, player skills/spells in existing Handler, packet time at queue admission rather than racing the global GameTime on worker. Sorting/filtering retains previous comparisons; item usability helper mirrors old predicates. Time left is request-time rather than worker-time (intentional safety trade-off; native parity check needed).
- All-faction policy publication builds complete retagged candidate and views under the same mutation lock, swaps as a unit. Add/remove/bid cannot interleave inside rebuild (equivalent serialization, no replay backlog); every worker sees a complete pinned generation, no per-worker readiness barrier. Failure leaves old active policy + rows untouched; new auction with failed classification remains Unknown, never disappears from management. Classifier must be pure, non-reentrant, copied facts only; real provider not registered. Catalog::Publish exercised by synthetic tests only, not called by native Core. New native catalog defaults Disabled gen1; QueueSearchRequest rejects non-Disabled browse until authoritative viewer/revision seam is installed.
- Default/detailed filters check visibility before append/sort/page/count. getAll deliberately bypasses detailed criteria; capped scan legacy Disabled/Observe and full eligible count Enforced. Owner/bidder routes never filter by progression. Existing transaction/pricing/auctionability code unchanged.
- WorldSession::SetPlayer assigns process-local monotonic non-reused incarnation; normal PlayerStorage::LoadFromDB and same-character CharacterHandler reconnect use SetPlayer, logout/failed login clear. Browse request stamp binds policy generation/GUID/incarnation/eligibility revision. World-side Searcher::Update checks actual active policy + matching current session before send, drops stale response without retry. Native Disabled revision1 is constant because progression has no effect; Enforced/Observe provider capture and revalidation not wired, deliberately refuse. Synthetic same-generation revision changes tested. No real provider IDs or classification.
- Request admission covers queued/running/response pending, total128/browse64 draft limits reserve capacity for management, close before queue Cancel and worker join. Overload drops without retry; native load/UX decision required, not owner-approved production thresholds. Memory relative to actual auction count: <=128 outstanding pinned views plus current/candidate, response packets and per-request copied facts. Not an absolute byte bound; production profiling, request payload size and snapshot copy costs remain open. No worker update/replay queue.
- Source ownership: auction sell/remove/bid opcodes PROCESS_THREADUNSAFE, browse/owner/bidder PROCESS_THREADSAFE. World update sessions before MapMgr; MapMgr waits map workers; auction response Update on world side. Capture snapshot from handler/queue owner; worker never uses catalog object. Future provider activation must preserve world-side serialized generation/revision validation through actual packet send.
