## Integration proposal (not implemented)

1. Record keyed by GUID and authoritative IP login epoch; immutable value copies only. No lock held across callbacks, inventory operations or IP calls. Scope guards invalidate before mutations/callbacks, remain Unknown across nested/reentrant operations and never publish on scope exit. Unknown while no valid session/capability capture, or revision exhausted. Validate owner-thread ownership explicitly.
2. Establish a real stable owner-thread capture/republish boundary, after enclosing operation completes and IP registration known; do not publish from equipment visual, equip or skill callbacks. Capture ticket, read exact level/equipment/eligibility facts, publish only if ticket/session/revision still current. Worker readers get copies, not Player pointers. A separate final coherent B check must immediately precede command mutation; cross-thread command dispatch needs owner-thread execution.
3. The fixed denominator uses eligibility independent of current occupancy. Count empty eligible slots as zero; removal cannot raise the cap. Policy parameters (optional-slot thresholds, two-hand weights, ranged eligibility) require review; no numeric defaults selected here. Invalid/unknown capabilities refuse; explicit zero vs unknown must be preserved for later policy. Do not reuse occupied-only prototype.
4. Before runtime patch, complete cross-file callers and writer inventory, lifecycle/epoch binding, capability capture schema, stable owner-thread boundary, and no-IP interface/fallback. Do not claim this limited audit covers every direct writer, module callback or thread.
